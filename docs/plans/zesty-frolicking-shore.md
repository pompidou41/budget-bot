# План: Временное сообщение при парсинге таблицы

## Контекст

При регистрации пользователь отправляет ссылку на Google Sheets. Бот выполняет два сетевых запроса: проверяет доступ (`verifySheetAccess`) и парсит категории (`parseBriefCategories`). Эти запросы занимают несколько секунд, в течение которых пользователь не получает никакой обратной связи. Нужно сразу отправить временное сообщение «Подключаю таблицу...», а после завершения — заменить его итоговым ответом через `editMessageText`.

## Файл для изменения

`src/bot/handlers/registration.ts` — функция `handleRegistrationText()`, строки 184–266.

## Реализация

### Шаг 1: Отправить loading-сообщение после валидации URL

После строки 192 (после того как `extractSheetIdFromUrl` вернул не-null), **до** первого сетевого запроса:

```typescript
const loadingMsg = await ctx.reply('Подключаю таблицу...');
```

### Шаг 2: Заменить `ctx.reply` на `editMessageText` во всех ветках

Вместо создания нового сообщения — редактировать loading-сообщение через `ctx.api.editMessageText(ctx.chat!.id, loadingMsg.message_id, ...)`.

**Ветка `!access.ok`** (строки 197–207):
```typescript
await ctx.api.editMessageText(
  ctx.chat!.id,
  loadingMsg.message_id,
  `Нет доступа к таблице. Убедись, что добавил\n` +
    `<code>${env.GOOGLE_SERVICE_ACCOUNT_EMAIL}</code>\n` +
    `как редактора.\n\n` +
    `📖 <a href="${TELEGRAPH_GUIDE_URL}">Инструкция по подключению</a>\n\n` +
    `Если проблема не решается — пиши @pompidou17.`,
  { parse_mode: 'HTML' },
);
```

**Ветка `!parsed` (нет листа «Сводка»)** (строки 236–241):
```typescript
await ctx.api.editMessageText(
  ctx.chat!.id,
  loadingMsg.message_id,
  `Таблица «${access.title}» подключена.\n\n` +
    `Лист "Сводка" не найден — использую стандартные категории.\n\n` +
    `Регистрация завершена!`,
);
await ctx.reply(WELCOME_TEXT, { parse_mode: 'HTML' });
```

**Ветка успеха с категориями** (строки 262–265):
```typescript
await ctx.api.editMessageText(
  ctx.chat!.id,
  loadingMsg.message_id,
  msg,
  { parse_mode: 'HTML', reply_markup: categoriesConfirmKeyboard() },
);
```

## Итоговый UX-флоу

1. Пользователь присылает ссылку
2. Если URL невалидный → мгновенный ответ с ошибкой (без loading, т.к. проверка синхронная)
3. Если URL валидный → бот сразу отправляет «Подключаю таблицу...»
4. После сетевых запросов loading-сообщение редактируется:
   - Нет доступа → сообщение об ошибке
   - Нет листа «Сводка» → успех + стандартные категории, затем WELCOME_TEXT
   - Успех с парсингом → список категорий + кнопки подтверждения

## Верификация

1. Запустить бота: `npm run dev`
2. Пройти регистрацию: /start → нажать «Добавил» → отправить ссылку на таблицу с доступом
3. Убедиться, что сразу появляется «Подключаю таблицу...», а потом оно меняется на список категорий
4. Проверить кейс без доступа: отправить ссылку на таблицу без прав — сообщение должно смениться на ошибку
5. Проверить кейс без листа «Сводка»: ссылка на таблицу без этого листа — сообщение должно смениться на «Регистрация завершена!» + WELCOME_TEXT
