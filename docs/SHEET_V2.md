## 1. Листы таблицы и их роль

| Лист | Роль | Можно ли писать боту |
| --- | --- | --- |
| **Операции** | Единственное место ввода движений денег. Одна строка = одно событие (доход / расход / перевод). | Да — только столбцы A:L |
| **Счета** | Справочник счетов/карт/вкладов/кредитов. Остатки — формулы от «Операции». | Нет (кроме, возможно, разового добавления нового счёта — строка A:L, но J:K не трогать) |
| **Курсы** | Курсы валют к USD (авто через GOOGLEFINANCE + ручной override) и история курса USD/RUB по дням. | Нет, кроме ручного курса в D при необходимости |
| **Categories** | Справочник категорий/подкатегорий. | Нет (можно только добавлять новые строки в конец, если нужна новая категория) |
| **Дашборд** | Капитал по группам счетов, графики, сводка за 12 месяцев. Полностью формулы. | Нет |
| **Категории по месяцам** | Среднее/медиана/перцентили по категориям и по месяцам, с разделением на регулярные и разовые траты. Полностью формулы. | Нет |
| **Недели** | Траты по категориям и «неделям» (1–8 / 9–16 / 17–24 / 25–конец месяца) за 6 месяцев, переключатель USD/RUB, тепловая карта. Только формулы; создаётся скриптом `yarn weeks-sheet` (§8). | Нет |
| **Капитал** | Капитал и сбережения во времени: точки по неделям (1, 9, 17, 25 числа) или по месяцам (1-е) с «Даты начала» счетов и «сейчас», Δ к прошлой точке, по группам счетов, график. Только формулы; создаётся скриптом `yarn capital-sheet` (§9). | Нет |
| **_Недели** | Скрытый лист-помощник для «Недели»: одна формула, плоская таблица доходов/расходов с суммой в выбранной валюте и датой бакета (§8). | Нет |
| **_Подкатегории** | Скрытый лист-помощник: строка N — подкатегории категории из «Операции»!G(N), для зависимого выпадающего списка в H (§10). | Нет |
| **Инструкция** | Текстовое описание для человека, как вести учёт. | Нет |
| **Подписки** | Ручной список регулярных подписок и их стоимости (сумма подтягивается в Дашборд). | Не относится к операциям, отдельный список |
| **копия Сводки** | Архив прежнего способа ведения учёта (2025–2026), больше не используется для ввода. | Нет, только чтение при необходимости истории |
| **Отчеты** | Старые отчёты поверх «копия Сводки». Не трогать, ссылается на архивный лист. | Нет |

## 2. Лист «Операции» — основная точка записи

Шапка (строка 1), по столбцам:

| Кол. | Заголовок | Кто заполняет | Тип / формат |
| --- | --- | --- | --- |
| A | Дата | вводится | дата |
| B | Тип | вводится | один из: `Расход`, `Доход`, `Перевод` |
| C | Счёт | вводится | ID из листа «Счета» (столбец A) — счёт списания (для дохода — счёт зачисления) |
| D | Сумма | вводится | число > 0, в валюте счёта C |
| E | Счёт куда | вводится, **только для Перевод** | ID счёта-получателя из «Счета» |
| F | Получено | вводится, **опционально для Перевод** | сумма в валюте счёта E. Если пусто — считается, что пришла та же сумма D (годится только если валюты C и E совпадают; при разных валютах это поле обязательно) |
| G | Категория | вводится | значение из «Categories», столбец A |
| H | Подкатегория | вводится | значение из «Categories», столбец B (см. §4 — список не фильтруется по категории на уровне валидации листа) |
| I | Комментарий | вводится | произвольный текст, на что/зачем операция |
| J | Разовая | вводится | чекбокс. Отмечаются крупные нетипичные траты (курсы, техника, разовая поездка) — они не портят медиану/среднее по обычным категориям в «Категории по месяцам» |
| K | Курс (ручной) | вводится, опционально | если задано — используется вместо курса из листа «Курсы» на эту операцию. Формат — как валюта счёта C (для RUB: рублей за 1 USD, напр. 86.5) |
| L | Добавлено | бот | дата и время записи строки (`dd.mm.yyyy hh:mm`, часовой пояс `BOT_TIMEZONE`). «Дата» (A) — когда операция совершена, «Добавлено» — когда её внесли. У строк до 17.10.2026 здесь скопирована «Дата» (настоящего времени записи для них нет); строки, внесённые руками, бот не помечает |
| M | Валюта | формула | валюта счёта C (VLOOKUP в «Счета») |
| N | Курс | формула | K, если задан, иначе курс на дату A из «Курсы» (для RUB — по истории дневных курсов, для остальных валют — текущий действующий) |
| O | Сумма USD | формула | пересчёт D в USD по курсу N |
| P | Валюта получ. | формула | валюта счёта E (для переводов) |
| Q | Курс получ. | формула | аналогично N, но для валюты P |
| R | Получено USD | формула | пересчёт «Получено (расч.)» (T) в USD по курсу Q |
| S | Потеря на обмене USD | формула | `O − R`. Разница между USD-оценкой отправленного и полученного — показывает спред/комиссию обмена |
| T | Получено (расч.) | формула | F, если задано, иначе D (см. правило в F) |
| U | Месяц | формула | первое число месяца операции — по нему считаются все агрегаты |

**Важно:** столбцы M:U — формулы. Каждая — одна `ARRAYFORMULA` **в ячейке шапки** (строка 1) вида
`={"Валюта";ARRAYFORMULA(IF(C2:C="","",…))}`: заголовок и под ним значения для всех строк. В строках 2+ этих
колонок нет содержимого, только вывод массива, поэтому строки данных можно сортировать, вставлять и удалять как угодно —
формулы это не задевает. Диапазон M1:U защищён (warning-only protection): Sheets спрашивает «Heads up!» перед
правкой серых колонок и при каждой сортировке из меню фильтра (так делает любая защита внутри диапазона фильтра —
сортировке это не мешает, жмёшь OK; галочка гасит окно на 5 минут). Если всё же вписать значение в серую ячейку M:U,
массив этой колонки не сможет развернуться (`#REF!` в шапке) — достаточно удалить вписанное. Бот пишет только A:L.

До 17.10.2026 формулы стояли в строке 2 (первой строке данных), и сортировка уносила их вниз — таблица ломалась.
Миграция: `scripts/migrate-added-column.ts` (`yarn migrate-sheet`).

**Сортировка.** Фильтр шапки покрывает `A1:U`: сортировать можно из меню фильтра любой колонки, в том числе по
«Дате» (когда совершена) и по «Добавлено» (когда внесена). Остатки, «Дашборд» и «Категории по месяцам» считаются
`SUMIFS` по целым колонкам и от порядка строк не зависят.
Сортировка в Sheets одноразовая, поэтому после каждой записи бот растягивает диапазон фильтра до конца листа (если он короче) и заново применяет текущие `sortSpecs` фильтра (`sortRange` по строкам 2..конец): новые строки встают туда, куда их поставила бы последняя выбранная владельцем сортировка. Пустые строки Sheets всегда сортирует вниз. Сбой обновления фильтра только логируется, запись не откатывается.

**Архив.** Строки счёта `ARCHIVE` скрыты **фильтром** по колонке «Счёт» (а не скрытием строк вручную: скрытые
вручную строки привязаны к номерам, и после сортировки под ними оказывались бы другие операции). Показать архив —
в меню фильтра «Счёт» отметить `ARCHIVE`.

Данные о типах для колонки B: `Расход | Доход | Перевод`.
Данные о `Разовая` (J) — булево, чекбокс.

История до сентября 2026: за 01.01.2023–30.09.2025 — только операции Т-Банка из PDF-выписок (`T_MAIN`, `T_SACC` с 03.2025; импорт 24.11.2026, 3666 строк; других банков и наличных за этот период нет, зарплата до 07.2024 приходила в другие банки и видна только как переводы; закрытые накопительные и кредитка — `Перевод` с/на `ARCHIVE`). За 01.10.2025–31.08.2026 — настоящие операции Т-Банка из PDF-выписок (`T_MAIN`, `T_SACC`, `T_SAVE`, `T_MONTHLY`, `T_CC`, закрытый `T_6809`; импорт 24.11.2026, 1540 строк, округления свёрнуты по неделям), плюс строки `ARCHIVE` «Другие источники (нал, другие банки) — …»: недельные суммы старой «копии Сводки», уменьшенные так, чтобы итог Расхода и Дохода каждого месяца остался прежним. Переводы в свои другие банки, снятие наличных и пополнения из них — `Перевод` с/на `ARCHIVE`. У `ARCHIVE` «Дата начала» 01.09.2026 и начальный остаток 50 168, поэтому история не меняет его остаток; остальные счета начинаются с сентября.

## 4. Лист «Categories» — категории и подкатегории

Столбцы A:T (сверено с живой таблицей 11.09.2026):

- **A** — Категория (повторяется по строкам для каждой подкатегории — плоский список пар).
- **B** — Подкатегория, парная к A в этой же строке.
- **C** — пустой столбец-разделитель.
- **D:… (до CategoryList)** — по одной колонке на каждую категорию верхнего уровня (заголовок = имя категории), в колонке вниз — допустимые подкатегории именно этой категории. Это более удобный источник для двухшагового выбора «категория → подкатегория» (сначала показать список заголовков, затем непустые значения в найденной колонке), чем плоская пара A/B. Бот читает `Categories!C1:AZ`, пропускает пустые столбцы в начале и останавливается на `CategoryList`, поэтому новая категория-столбец перед `CategoryList` подхватится сама.
- **T (CategoryList)** — полный список категорий верхнего уровня (тот же список, что заголовки D:S).

Категории верхнего уровня сейчас: `Income, Housing, Food, Transport, Health, Personal, Subscriptions, Entertainment, Travel, Education, Family, Liza, Projects, Finance, Investments, Transfer, Other`. Столбцов D… столько же, сколько категорий; `Projects` (по-русски «Проекты») — личные проекты владельца.

Примеры подкатегорий (полный список — в листе, может расти):

- Transport: Fuel, Public transit, Taxi & rideshare, Parking, Car maintenance, Car insurance, Car loan payment, Other
- Health: Doctor, Pharmacy, Gym & fitness, Other
- Personal: Clothing, Beauty & grooming, Shopping
- Subscriptions: Streaming, Cloud storage, News & media, Mobile plan, AI, VPN, Other
- Entertainment: Cinema, Concerts & events, Games, Books, Hobbies, Other
- Travel: Flights, Hotels, Transport (trip), Food (trip), Activities, Visa & docs
- Education: Courses, Books & materials, Tuition, Study loan payment, Other
- Family: Gifts, Pets, Support to family, Other
- Liza: Flowers, Gifts, Other, Allowance, Health, Beauty & care, Clothing
- Projects: Ads, Hosting & servers, Domains, AI & APIs, Tools & services, Contractors, Other
- Finance: Bank fees, Interest paid, Taxes, Currency exchange loss, Documents & fees, Loan given

Эти названия — на английском (унаследовано от прежней версии листа Categories, которую вёл сам пользователь). Значения в «Операции».G/H пишутся ровно как в этом справочнике.

## 5. Лист «Курсы»

Столбцы A:F (строки данных с 4-й):

| Кол. | Заголовок | Формат |
| --- | --- | --- |
| A | Валюта | тикер: `USD, RUB, USDT, EUR, BTC, ETH` |
| B | Формат | `за 1 USD` (сколько единиц валюты за доллар, напр. RUB) или `USD за 1` (цена единицы в долларах) |
| C | Авто (GOOGLEFINANCE) | формула, тянет текущий курс |
| D | Ручной | если заполнено — перекрывает C |
| E | Действующий | формула: D, если задано, иначе C — это и есть «текущий курс», на него ссылаются другие листы |
| F | Примечание | |

USDT считается по паритету 1:1 к USD (не через рынок).

Справа (диапазон `H4:I`, заголовки «Дата» / «USDRUB» в H3:I3) — история дневных курсов USD/RUB с 01.01.2025 по сегодня (дата | курс), формулой `GOOGLEFINANCE(..., "DAILY")`. По ней в «Операции».N ищется курс на дату конкретной операции (приблизительный VLOOKUP по дате, для другой валюты, кроме RUB — берётся текущий действующий курс E, истории по остальным валютам сейчас нет).

Новая валюта = новая строка в этом листе (плюс проверить, что тикер используется в «Счета».E при необходимости).

## 6. Бизнес-правила, которые стоит знать

- **Перевод** — единственный способ показать движение денег между своими счетами, включая обмен валют и покупку/вывод USDT. Расход/Доход никогда не затрагивают два счёта.
- Если у перевода валюты счетов C и E различаются, поле F («Получено») обязательно нужно указывать — иначе расчёт «Потери на обмене» (S) будет считать по номиналу, а не по факту.
- «Разовая» (J) — управляет только статистикой в «Категории по месяцам» (средние/медианы), на остатки счетов и капитал не влияет.
- «Курс (ручной)» (K) — override курса именно этой операции (например, реальный курс банка на конкретный обмен), а не общий курс на дату.
- Начальные остатки счетов (Счета.H) — это снимок примерно на май 2026 года (взято из прежнего листа Accounts), не 100% актуальны на сегодня; дата снимка — в примечании ячейки H1 листа «Счета».

## 7. Контекст: что было раньше (для справки, коротко)

До этой сессии учёт вёлся в листе «копия Сводки» (по неделям/месяцам, формулами вида `=1500+3000` в ячейках), с отдельным листом «Сводка», из которого бот в этом репозитории (`budget-bot`) читал список категорий и куда писал агрегированные суммы (`src/sheets/brief-parser.ts`, `src/sheets/brief-updater.ts`). Модель транзакции бота была плоской: `Date | Type | Category | Amount | Comment`, без счетов, без валют, без переводов, без курсов, без крипты.

Лист «Сводка» в этом состоянии таблицы больше не существует (переименован/удалён при пересборке), «копия Сводки» оставлена как архив только для чтения. Новая модель («Операции» v2 выше) полнее: счета, валюты, переводы, курсы, разовые траты — то, чего в прежней модели бота не было вовсе.

Дальнейшие решения — держать ли бота мультиюзерным, как встраивать счета/переводы/курсы в UX бота, какой хостинг и креды использовать — вне рамок этого документа.

## 8. Листы «Недели» и «_Недели» — отчёт по неделям

Лист для глаз, как прежняя «копия Сводки»: строки — категории и подкатегории, колонки — «недели» месяца, на пересечении сумма. Только формулы, бот его не читает и не пишет. Создаёт скрипт `scripts/create-weeks-sheet.ts` (`yarn weeks-sheet`), раскладку и формулы строит `src/sheets/weeks-layout.ts`. «Недели» стоит сразу после «Категории по месяцам», `_Недели` скрыт.

**Бакеты.** Месяц делится по дню на четыре части: 1–8, 9–16, 17–24, 25–конец месяца (дата берётся без времени). Строки ARCHIVE датированы ровно 1/9/17/25-м, поэтому ложатся в бакеты один в один. Окно — 6 месяцев по 5 колонок (4 бакета и Σ месяца), D:AG.

**Управление** (жёлтые ячейки; всё остальное — формулы):

| Ячейка | Что | По умолчанию |
| --- | --- | --- |
| B2 | Валюта отчёта: `USD` или `RUB` (список). RUB — это USD × курс USDRUB на дату операции (`'Курсы'!H4:I`, приблизительный VLOOKUP, как в «Операции».Курс; до начала истории — текущий курс из строки RUB), у операций в RUB — сумма как есть | `USD` |
| B3 | «С разовыми» (чекбокс): выключен — разовые расходы (J) считаются нулём, как в «Категории по месяцам» | выключен |
| B4 | «Первый месяц»: любая дата нужного месяца; пусто — последние 6 месяцев, текущий справа | пусто |

**Строки** (раскладка не меняется, пока не пересоздан лист):

| Строка | Содержимое |
| --- | --- |
| 1 | Заголовок и статус сверки в C1: `✓ сходится` / `⚠ есть траты вне категорий` |
| 2–4 | Управление (B2:B4) |
| 5–6 (скрыты) | Даты начала бакетов (у Σ — 1-е число месяца) и маркеры `w` (неделя) / `m` (Σ) |
| 7 | Название месяца по-русски; у текущего — «(по дд.мм)» |
| 8 | Шапка: «Категория, <валюта>», «Тренд», «Норма/мес», `1–8` `9–16` `17–24` `25–<конец>` `Σ` |
| 9–11 | Доходы итого · Расходы итого · Сбережения (доходы − расходы) |
| 13… | Категории расходов — все верхнего уровня из «Categories», кроме `Income` и `Transfer` (сейчас 14): жирная строка категории (по-русски: Жильё, Еда, …), её подкатегории, строка «без подкатегории / прочее» = категория − подкатегории. Дети каждой категории свёрнуты в группу строк |
| последняя | «Контроль: вне категорий» = «Расходы итого» − сумма категорий; должна быть 0, иначе строка красная, а в C1 предупреждение |
| AH:AJ (скрыты) | Ключ категории, ключ подкатегории и тип строки (`in out sav cat sub rest ctl`), по ним однотипные формулы сетки |

«Тренд» — SPARKLINE по недельным клеткам всех 6 месяцев. «Норма/мес» — медиана 6 последних **полных** месяцев по этой строке, от окна и B4 не зависит. Цвет клеток — шкала от белого до оттенка относительно максимума своей строки (категории насыщеннее подкатегорий, «Сбережения» красный → белый → зелёный); Σ месяца красная, если выше нормы больше чем на 30%.

`_Недели` — одна `ARRAYFORMULA` в A2 под заголовками `Дата | Тип | Категория | Подкатегория | Разовая | USD | RUB | Сумма | Неделя | Месяц`: доходы и расходы из «Операции» (в том числе строки ARCHIVE — формулы фильтр не учитывают), «Сумма» уже в валюте B2 и с учётом B3. Колонки «Операции» скрипт находит по заголовкам, а после `yarn migrate-sheet` (вставка колонки L) ссылки в формулах сдвигаются сами — лист можно создать до миграции.

**Что знать**

- `TODAY()` в формулах — по часовому поясу **таблицы** (Asia/Yekaterinburg), а не `BOT_TIMEZONE`: «последние 6 месяцев», «по дд.мм» и норма переключаются в полночь по таблице.
- Подкатегории и категории фиксируются при создании. Новая подкатегория в «Categories» суммы не ломает — её траты идут в «без подкатегории / прочее» своей категории; новая категория верхнего уровня видна только в «Контроль: вне категорий» (красный). Чтобы они появились отдельными строками: `yarn weeks-sheet --apply --replace` (оба листа пересоздаются, там только формулы; управление вернётся к значениям по умолчанию). `yarn weeks-sheet --check` ничего не меняет: проверяет листы и перечисляет то, чего на них нет.
- Защита warning-only только на `_Недели`. Сетка «Недели» не защищена: любая защита строк вызывает «Heads up!» на каждое сворачивание группы. Случайно затёртую формулу чинит `yarn weeks-sheet --apply --replace`.
- Скрипт на живой таблице требует `--live`; по умолчанию печатает план (dry run). После записи проверяет: ни одной ошибки `#…`, контроль 0, а в USD без разовых «Расходы итого» по месяцам равны строке «Регулярные расходы, итого» из «Категории по месяцам».
- Нагрузка: около 2400 `SUMIFS` по целым колонкам `_Недели` и около 600 внутри `MAP` для нормы пересчитываются при каждой правке «Операции». Если станет тормозить — заменить сетку на агрегирующий `QUERY` в `_Недели`.

## 9. Лист «Капитал» — динамика капитала и сбережений

Растут или падают деньги: остатки всех счетов капитала на каждую «неделю» (1, 9, 17, 25 числа, как бакеты «Недель») или на 1-е число месяца — переключатель «Шаг» в B3. Дневного ряда нет. Только формулы,
бот его не читает и не пишет. Создаёт скрипт `scripts/create-capital-sheet.ts` (`yarn capital-sheet`: dry-run по
умолчанию — печатает план и ожидаемые числа; `--apply [--replace] [--live]`, `--check`), формулы строят
`src/sheets/capital-layout.ts` и `capital-values.ts`, оформление и график — `capital-format.ts`, проверку —
`capital-check.ts`. Лист встаёт сразу после «Дашборда».

**Какие счета.** Капитал — счета с галочкой «В капитале» (G) **и закрытые** (группа или тип `Архив`): сейчас у
закрытых 0, но раньше на них лежали деньги, и без них прошлое занижалось бы. Служебный `ARCHIVE` (сводки истории) не
входит. Закрытые идут отдельной колонкой «Закрытые». **Сбережения** — группы `Подушка + Накопления + Инвестиции +
Крипта` (без Текущих, Ежемесячных, Кредитов и закрытых).

**Остаток на дату** («на утро»): начальный остаток H + движения с датой ≥ «Дата начала» (I) и < даты точки — ровно
как «Счета»!J (доход +D, расход и перевод со счёта −D, перевод на счёт +«Получено (расч.)» T). Остатки известны только
с «Даты начала», поэтому первая точка — самая ранняя «Дата начала» (сейчас 11.09.2026); раньше данных нет, оценок лист
не строит. Последняя строка «сейчас» учитывает все операции и совпадает с «Дашборд»!B12 и суммой «Счета»!K.

**Курсы.** Всё по **текущим** курсам «Курсы»!E (как «Дашборд»): изменения показывают движение своих денег, а не
колебания курса. B2 — валюта (`USD` / `RUB`, RUB = USD × текущий курс RUB), B3 — шаг (`Недели` / `Месяцы`): от него зависят строки таблицы, Δ и график.

**Раскладка:**

| Где | Что |
| --- | --- |
| A1, C1 | Заголовок и подпись «остатки известны с …» |
| B2, B3 | Валюта и шаг (жёлтые, списки) — единственные редактируемые ячейки; остальное под warning-защитой |
| строки 4–6 | Капитал и Сбережения: «Сейчас», «За месяц (с dd.mm)» — Δ к первой **недельной** точке не старше месяца и % (от шага не зависит: считается по своей скрытой строке Q7), «С <начала>» — Δ и %; рост зелёный, падение красное |
| A8 | Линейный график «Капитал» и «Сбережения» |
| строка 24 | Шапка таблицы: Дата · Капитал · Δ · Сбережения · Δ · Текущие · Ежемесячные · Подушка · Накопления · Инвестиции · Крипта · Расчёты · Кредиты · Закрытые |
| строки 25… | По строке на точку выбранного шага; строки добавляются сами (всё — растекающиеся формулы от `TODAY()`) |
| O (скрыта) | O2 — множитель валюты, O3 — число точек, O4 — недельная точка «месяц назад», O5 — начало (самая ранняя «Дата начала»), O25… — срезы (serial; «сейчас» = 31.12.9999) |
| Q:BX (скрыты) | Q2:Q6… — по колонке на счёт: ID, группа, начальный остаток, «Дата начала», курс к USD; Q7… — остатки в USD на точку O4 (для сводки); Q25… — матрица остатков в USD (точки × счета, `MAKEARRAY` с четырьмя `SUMIFS`). Колонки групп — `MMULT` матрицы на маску группы |

Матрица рассчитана на 60 счетов (колонки Q:BX); больше — пересоздать лист с бо́льшим `MAX_ACCOUNTS`. Новый счёт в
«Счета» подхватывается сам. `yarn capital-sheet --check` пересчитывает каждую точку из сырых значений «Операции» и
«Счета» и сверяет с листом.

## 10. Расчёты с людьми, категория Projects, `_Подкатегории` (v2.19)

Одноразовая миграция `yarn settlements-sheet` (`scripts/setup-settlements.ts`; dry-run по умолчанию печатает план,
`--apply [--live]` пишет; идемпотентна — повторный запуск ничего не делает). Перед `--apply` оператор делает
`yarn backup-sheet`. Данные «Операции» скрипт не трогает. Планирование — `src/sheets/settlements-plan.ts`,
`subcategories-plan.ts`, запросы — `settlements-requests.ts`.

**Расчётные счета** (тип и группа `Расчёты`, в капитале, начальный остаток 0, дата начала 01.09.2026):

| ID | Название | Валюта |
| --- | --- | --- |
| `LIZA_GEL` | Расчёты с Лизой | GEL |
| `DEBTS_RUB` | Долги людей (₽) | RUB |
| `DEBTS_GEL` | Долги людей (₾) | GEL |

Знак остатка: **плюс — должны владельцу, минус — владелец должен**. Деньги, которые ходят туда-сюда (Лиза прислала,
владелец заплатил за неё, заём другу и его возврат), — это **Перевод** между реальным счётом и расчётным
(категория `Transfer` / `Settlement`), а не Расход/Доход; траты и подарки без возврата остаются Расходом. Кто именно —
в комментарии. Бот: кнопка `↔️ Расчёт` на карточке, подсказка в `/balance`, правила в AI-промптах. Тип `Расчёты`
добавлен в выпадающие списки «Счета»!D и F (строки 2–1001); в «Дашборд» перед «Кредиты» вставлена строка группы
«Расчёты» (формулы строки выше, итоги `SUM(B5:B12)` расширились); в «Капитал» — колонка группы «Расчёты» (лист
пересоздаётся `yarn capital-sheet --apply --replace --live`).

**Categories.** Новые пары дописаны в конец A:B. Прежние формулы в D:S имели фиксированную высоту (Income — 9
подкатегорий, а формул 7) и тихо теряли хвост списка, поэтому бот не видел Income/Cashback и Income/Interest. Теперь
в строке 2 каждого столбца категории одна растекающаяся `=IFERROR(FILTER($B$2:$B,$A$2:$A=D$1,$B$2:$B<>""),"")`,
строки 3+ пусты (под растеканием ничего не должно лежать). Из-за `Projects` для `TRANSPOSE(UNIQUE(…))` в D1 нужен
ещё один столбец, поэтому перед `CategoryList` вставлены столбцы (их число считается по данным), `Projects` дописан
в `CategoryList`. Валидация «Операции»!G/H (`Categories!$A$2:$A$300`) покрывает новые строки.

**«Категории по месяцам»:** строка `Projects` вставлена перед `Other`, формулы — копия строки выше.

**`_Подкатегории` и зависимый список в «Операции»!H.** Валидация H раньше показывала все подкатегории. Скрытый лист
держит строку на строку «Операции»: `A{N}` = `TRANSPOSE(FILTER(подкатегории, категория = INDEX('Операции'!$G:$G,ROW())))`.
`INDEX(…,ROW())`, а не `G{N}`, чтобы формулы переживали вставку, удаление и сортировку строк «Операции». Валидация
H2:H{rowCount} — `ONE_OF_RANGE ='_Подкатегории'!$A2:$T2`, строка относительная, `strict: false`. Это правило ставится
**только вручную в интерфейсе** (Данные → Проверка данных): Sheets API хранит любой диапазон в таком правиле как
абсолютный (`$A$2:$T$2` у всех строк — проверено 23.11.2026), а интерфейс сохраняет строку относительной. Поэтому
`yarn settlements-sheet` правило H не пишет, а только сверяет и печатает шаги. Ещё одна ловушка API: `setDataValidation`
не трогает строки, скрытые фильтром (архив в «Операции», счета без «В капитале» в «Счета») — перед такой правкой
фильтр снимают и возвращают. Лист рассчитан на
`N = max(6000, 2 × rowCount «Операции»)` строк. За их пределами выпадающий список пуст, но ввод разрешён (валидация
не строгая). `yarn check-sheet` предупреждает, когда заполнено ≥80% N; продлить — повторный `yarn settlements-sheet --apply`.
